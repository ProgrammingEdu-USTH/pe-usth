# AD84 · PostgreSQL Node, Datum và tuple

Đã học: AD55, AD57; AD83 cho ownership và memory context. Nguồn: DSC7e online §32.8.5–32.8.7, gồm §32.8.5.1–32.8.5.2. Môi trường web: source browser, editor pseudocode và canvas biểu diễn; workspace phát triển PostgreSQL 18 ở backend là capability cần triển khai. Code dưới đây phục vụ đọc API/mô hình, chưa được compile hoặc xác nhận ABI.

Một đoạn C lấy field từ slot, thấy giá trị số bằng 0 rồi kết luận đó là SQL NULL. Đoạn khác cast mọi `Node *` thành cùng một loại biểu thức vì “đều là node”. Cả hai bỏ qua metadata, nhưng bỏ qua hai loại metadata khác nhau: tag của cấu trúc cây và type/null flag của giá trị SQL. Hiểu ranh giới này giúp đọc internals mà không tự đoán ý nghĩa của một địa chỉ hoặc một word máy.

## Đọc struct và cast ở mức cần dùng

`typedef` đặt tên kiểu; `struct` nhóm các field. `Node *p` là pointer, `p->type` đọc field qua pointer, còn `(SomeType *)p` yêu cầu C xem địa chỉ ấy theo một kiểu khác. Cast không cấp phát cấu trúc mới, không kiểm schema và không sửa dữ liệu. Nếu đối tượng thật không có layout được giả định, phép đọc field có thể không hợp lệ; không có một output sai cố định để lấy làm đáp án.

Quy ước Node của PostgreSQL đặt `NodeTag` ở đầu cấu trúc, trực tiếp hoặc qua parent struct đứng đầu. Một subtype có thể mở đầu bằng struct parent, như lớp state scan mở đầu bằng state chung. Nhờ quy ước prefix này, code có thể nhìn phần chung qua pointer parent. Chiều ngược lại cần biết tag thật, thay vì suy subtype từ kiểu khai báo pointer.

`makeNode(Type)` tạo node đúng tag; `IsA(p,Type)` so tag. Trong source nhánh 18 đã đọc, `castNode` kiểm tag bằng assertion khi build bật assertions; ở build khác nó có thể chỉ là cast. Vì vậy, không dùng `castNode` như cơ chế validation luôn có ở production. [Đối chiếu nodes.h](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/include/nodes/nodes.h). Pointer NULL cũng phải được xử lý theo hợp đồng trước khi đọc tag.

## Ví dụ 1: dispatch đúng và copy cả cây

Mô hình tự viết sau **không khai báo node mới trong server**. Nó chỉ giữ quy ước prefix để học C:

```c
typedef enum { AD_LITERAL, AD_ADD, AD_NEGATE } AdTag;
typedef struct { AdTag tag; } AdNode;
typedef struct { AdNode base; int value; } AdLiteral;
typedef struct { AdNode base; AdNode *left; AdNode *right; } AdAdd;
typedef struct { AdNode base; AdNode *child; } AdNegate;
```

Input là cây hữu hạn, không cycle, không sharing; Literal có số nguyên toán học, Add có hai child và Negate có một child. Output của `eval` là giá trị biểu thức; bài dùng số nguyên toán học trong mô hình để chưa phải giải overflow C. Input sai tag, thiếu child hoặc NULL ở vị trí bắt buộc bị báo lỗi mô hình.

```text
eval(node):
    require node != NULL
    switch node.tag:
        LITERAL: return node.value
        ADD: return eval(node.left) + eval(node.right)
        NEGATE: return -eval(node.child)
        otherwise: error("unsupported node")

clone(node, destination):
    require a well-formed finite tree
    allocate a fresh node of the same tag in destination
    copy scalar fields
    recursively clone every child into destination
    return the fresh root
```

Với cây `Add(Literal(7),Negate(Literal(2)))`, eval xử lý 7, rồi 2, rồi −2, cuối cùng 5. Clone tạo bốn node mới: Add, Literal 7, Negate và Literal 2. Đổi Literal 7 của cây gốc thành 9 sau copy: eval gốc thành 7, eval bản sao vẫn 5. Nếu chỉ làm `*copy = *original`, child pointers vẫn chung và thay leaf gốc cũng đổi ý nghĩa của “bản sao”.

Lập luận clone theo cấu trúc cây: với leaf, node mới có cùng tag/scalar, không alias node gốc. Với node trong, giả sử các bản sao child độc lập và giữ giá trị; thêm root mới cùng tag, gắn các child ấy thì cả cây vừa độc lập vừa giữ giá trị. Mỗi lời gọi đi xuống một subtree nhỏ hơn, nên hữu hạn thì dừng. Với N node và chiều cao h, eval/clone tốn O(N), stack O(h); clone cần thêm O(N) node, nếu mỗi scalar, allocation node và phép số học có chi phí hằng trong mô hình. Khi dùng số nguyên tùy độ dài, phải cộng chi phí theo số bit của toán hạng. Nếu cho graph có sharing/cycle, cần hợp đồng copy khác và bảng memo; không áp chứng minh cây nguyên dạng.

Trong PostgreSQL thật, `copyObject`, `equal`, `nodeToString` và `stringToNode` là các họ công cụ cho những node được hỗ trợ. Equality cấu trúc khác equality pointer; serialization phục vụ internals/debug không mặc nhiên là định dạng lưu bền ổn định giữa major versions. Walker duyệt child; mutator trả cây đã biến đổi theo hợp đồng của nó. Khi thêm field chứa child mà quên traversal/copy, optimizer có thể nhìn cây cũ hoặc bỏ sót biến đổi.

§32.8.5.1 trình bày quy trình sửa tag và các hàm hỗ trợ thủ công. Nhánh 18 có `gen_node_support.pl` và `pg_node_attr`: nhiều phần hỗ trợ được sinh. Quy trình đọc patch là xác định node tương tự, xem struct/attributes, kiểm phần sinh và các trường hợp thủ công, rồi kiểm walker/mutator và nơi sử dụng. Không yêu cầu mọi loại executor state phải có đủ mọi hàm copy/read/equal. [README về Node của PostgreSQL 18](https://raw.githubusercontent.com/postgres/postgres/REL_18_STABLE/src/backend/nodes/README).

## Datum mang giá trị, type đến từ hợp đồng khác

Một Datum là vỏ truyền giá trị trong interface nội bộ. Với kiểu by-value, nó mang biểu diễn giá trị; với kiểu by-reference, nó mang pointer tới biểu diễn. Datum không tự kèm SQL type hoặc null flag. Type có thể đến từ chữ ký hàm, expression state hay tuple descriptor; cờ NULL đi cùng theo interface. Do đó, cùng một word không cho phép tự quyết định nên gọi `DatumGetInt32`, giải mã pointer hay đọc boolean.

`Int32GetDatum(x)` và `DatumGetInt32(d)` là cặp chuyển phù hợp khi type đã được xác nhận là SQL integer không NULL. Chúng không thay phép cast SQL từ text sang integer. SQL NULL khác số 0, chuỗi rỗng và C NULL pointer. Khi null flag là true, không diễn giải payload Datum như một giá trị thông thường.

## Ví dụ 2: hai số 0 không cho cùng một kết luận

Descriptor giả định hai cột: `id integer`, `note text`; hàng A là `(0,NULL)`, hàng B là `(1,'')`. Bảng logic sau là input đã khai báo của mô hình, không phải dump bits từ server:

| Hàng/cột | Metadata type | isnull | Cách xử lý |
|---|---|---:|---|
| A.id | integer | false | giải mã integer, được 0 |
| A.note | text | true | kết quả SQL NULL, bỏ qua payload |
| B.id | integer | false | giải mã integer, được 1 |
| B.note | text | false | đọc text đúng API, được chuỗi rỗng |

Quy tắc sai `if (datum == 0) return NULL` có thể đánh nhầm A.id. Quy tắc sai “note có pointer nên luôn là chuỗi C” cũng không hợp lệ: `text` dùng representation có header, có thể nén hoặc TOAST, không hứa kết thúc bằng byte `\0`. Khi cần chuỗi C, phải chuyển qua API phù hợp với type và giữ đúng vòng đời bản chuyển.

Với kiểu varlena, input có thể dùng short header hoặc representation khác. Code phải dùng giao diện detoast/access phù hợp; không tự cast mọi pointer thành một struct có header bốn byte rồi đọc các field. Trường hợp packed còn cần chú ý alignment. Đọc vài giá trị text ngắn thành công không kiểm được các representation còn lại. [Tài liệu C functions](https://www.postgresql.org/docs/18/xfunc-c.html), [TOAST của PostgreSQL 18](https://www.postgresql.org/docs/18/storage-toast.html).

## Tuple vật lý khác mảng Datum của slot

`HeapTupleData` là một wrapper có độ dài, thông tin vị trí/quan hệ khi có ý nghĩa và pointer tới header/data của tuple. Chính wrapper không bảo đảm payload là một allocation độc lập do caller sở hữu. Nó có thể tham chiếu page được pin, một allocation kèm hoặc tách khỏi wrapper, hoặc các representation được adapter hỗ trợ. Không gọi `pfree` tùy ý lên mọi `t_data`, cũng không coi `ctid` là khóa logic lâu dài.

Heap row lưu header và payload theo layout của engine; nó không đơn giản là `Datum[]` nằm liền nhau trên disk. Descriptor cho biết attribute count, kiểu và thông tin độ dài/alignment cần đọc. Null bitmap có thể cho biết field nào vắng payload; với heap format được tài liệu mô tả, bit 1 là not-null, bit 0 là null. Không nhầm nó với boolean `isnull`, nơi true lại nghĩa là NULL. [Table row layout](https://www.postgresql.org/docs/18/storage-page-layout.html).

Một mô hình layout nhỏ cho ba field cố định có `(length,alignment)` lần lượt `(2,2),(4,4),(1,1)`, data bắt đầu ở offset 0: field 1 ở 0–1, padding ở 2–3, field 2 ở 4–7, field 3 ở 8. Nếu field 2 NULL và mô hình không dành payload cho NULL, field 3 ở offset 2. Đây là phép tính minh họa, không phải các offset heap thực được bảo đảm. Với field variable-length, còn phải đọc chiều dài/flags đúng representation. `base + column_number * sizeof(Datum)` không giải quyết layout đó.

`MinimalTuple` bỏ một số thông tin của heap tuple đầy đủ để phục vụ dữ liệu tạm khi không cần metadata ấy. Nó không tự có mọi system attribute. `TupleTableSlot` che nhiều khác biệt lưu trữ và có descriptor cùng các giá trị/null flags khi đã giải mã. Phải gọi accessor hợp lệ thay vì giả các arrays đã được điền đủ. Slot không tạo một bản sao độc lập cho mọi giá trị mà nó trả.

## Ví dụ 3: đọc hàng rồi giữ tên qua lần scan tiếp

Yêu cầu mới: scan hai hàng `(10,'An')`, `(20,'Binh')`, giữ note của hàng đầu sau khi scan đã dùng lại slot cho hàng hai. Đoạn đọc API sau giả định slot có descriptor đúng hai cột đã nêu, cột 2 là text, slot không rỗng:

```c
bool isnull;
Datum d = slot_getattr(slot, 2, &isnull);
/* Interpret d as text only when !isnull and the descriptor agrees. */
```

`&isnull` là địa chỉ biến boolean để accessor ghi cờ vào; attribute number ở interface này bắt đầu từ 1. Trước khi slot bị tái dùng, code lấy giá trị theo type, tạo bản sao **sở hữu độc lập** trong context R sống đủ lâu, rồi mới tiếp tục scan. Với yêu cầu chỉ giữ note, có thể chuyển thành chuỗi C và copy theo hợp đồng; nếu muốn giữ nguyên text/tuple, chọn API copy phù hợp với representation ấy.

Mô hình trace: slot→row 10; d mượn vùng note “An”; copy thành owned “An” trong R; scan row 20 tái dùng slot; owned “An” vẫn đúng. Chỉ sao `Datum saved=d` thì với by-reference ta vẫn chỉ có alias. Nó không được phép đọc sau khi nguồn mất hiệu lực, và không có expected rằng nó chắc chắn đổi thành “Binh”.

PG 18 phân biệt materialize slot với copy thành đối tượng caller sở hữu. Materialize loại phụ thuộc vào storage bên ngoài slot, nhưng không làm một pointer cũ sống qua mọi lần clear/reuse slot. `ExecCopySlotHeapTuple` cấp bản sao trong context caller; cần chọn context và quản lý kết quả đúng hợp đồng. Không giả mọi slot đều hỗ trợ system attribute. [Hợp đồng trong tuptable.h, REL_18_0](https://raw.githubusercontent.com/postgres/postgres/REL_18_0/src/include/executor/tuptable.h).

Thuật toán projection tổng quát nhận descriptor D, slot tương thích và tập cột cần lấy: với mỗi cột, kiểm phạm vi/type, lấy `(datum,isnull)`, nếu NULL thì ghi cờ NULL; nếu không, giải mã đúng type và copy mọi phần by-reference cần giữ sang owner kết quả. Bất biến sau k cột: output của prefix k đúng giá trị/nullness, và mọi dữ liệu output cần sống lâu đều độc lập nguồn. Bước tiếp theo giữ bất biến vì metadata quyết định decoder và phép copy hoàn thành trước tái dùng slot. Hết số cột hữu hạn thì dừng; output đúng toàn bộ projection. Chi phí gồm giải mã layout các cột cần đi qua và số byte được copy/detoast; không tuyên bố mọi `slot_getattr` là O(1).

Cụ thể hơn, SeqScanState mở đầu bằng ScanState, và ScanState mở đầu bằng PlanState. Nhìn prefix qua PlanState chỉ cho đọc các field chung; cast ngược cần biết đối tượng thật là SeqScanState. Một PlanState khác như state của join không có scan fields chỉ vì cùng parent. Tag đúng cũng không cho phép dùng pointer đã hết lifetime. Quy trình thêm node ở source 18 là sửa struct/attributes đầu vào cho generator, kiểm hỗ trợ sinh ra và phần thủ công, cập nhật walker/mutator cùng planner/executor consumers, rồi kiểm copy/read/write/equal theo loại node cần hỗ trợ. Không chỉnh tay một file sinh rồi bỏ source input.

Các đường tuple cần phân biệt: HeapTupleData có t_data=NULL là wrapper không trỏ tuple hợp lệ, khác một tuple hợp lệ có một field SQL NULL. Buffer tuple mượn payload trên page và cần pin; heap allocation có thể cùng chunk hoặc tách wrapper/payload; MinimalTuple bỏ metadata không cần cho dữ liệu tạm. Slot có thể là BufferHeapTuple, HeapTuple, MinimalTuple hoặc Virtual với Datum/isnull arrays. `get_heap_tuple` trả tuple do slot sở hữu, còn `copy_heap_tuple` trả bản sao caller sở hữu; `copyslot` sao sang destination slot với lifetime của destination. Clear/reuse slot có thể kết thúc quyền dùng payload mượn. Do đó không lấy một get accessor thay copy chỉ vì cả hai đều trả HeapTuple; chọn owner trước khi chọn API.

## Minh họa theo trạng thái

Canvas có hai lớp tách biệt: tag/layout Node và descriptor/value của tuple:

1. Root model có tag ADD, hai child hợp lệ; chưa đánh giá.
2. Dispatch chọn nhánh ADD, leaf 7 và NEGATE(2) cho kết quả 5; không cast node tùy ý.
3. Clone tạo bốn node độc lập; sửa leaf gốc không thay bản sao.
4. Slot chứa `(10,'An')`, descriptor xác nhận integer/text; d là reference mượn, isnull=false.
5. Copy note sang R; slot được clear/reuse cho `(20,'Binh')`; chỉ owned note còn hợp đồng dùng về sau.

Đây là mô hình giải thích, không phải output engine. Hoạt động hỗ trợ thứ nhất cho ghép tag với field được phép đọc. Hoạt động thứ hai cho tìm lỗi trong bảng type/null/owner và sửa nhánh decode. Nhiệm vụ chuyển giao thay input bằng `(0,NULL)` và thay yêu cầu thành giữ nguyên tuple, buộc giải thích cả NULL lẫn ownership.

## Luyện tập

1. Một function nhận `Node *p`, cast thẳng sang subtype Add rồi đọc `left`. Nêu tiền điều kiện còn thiếu, cách dispatch và vì sao không thể chấm bằng một kết quả crash cố định. `castNode` có luôn validate runtime không?
2. Với hàng A/B của ví dụ 2, sửa pseudocode dùng `datum==0` để phát hiện NULL. Ghi rõ metadata nào cần có trước khi decode integer/text.
3. Tự làm: thêm Multiply vào mô hình cây, eval và clone. Dùng cây `Multiply(Add(1,2),Negate(4))`; nộp trace, invariant/lập luận quy nạp, chi phí và một kiểm alias sau copy. Không tuyên bố đây là patch PostgreSQL đã chạy.
4. Slot được tái dùng mỗi lần next. Code lưu `Datum[]` của hai field bằng phép gán rồi clear slot. Điều gì có thể vẫn đúng cho integer, điều gì chưa được bảo đảm cho text? Đề xuất output contract và cách giữ dữ liệu cho cả hai trường hợp NULL/non-NULL.
5. Trong mô hình layout cố định đã cho, nếu field 1 NULL, field 2 và 3 không NULL, tính offsets từ data offset 0. Vì sao cách chia đều mỗi cột một word sai ngay cả khi chưa có text?

## Gợi ý

Mức 1: NodeTag phân loại cấu trúc; descriptor/signature phân loại Datum. Vẽ alias từ bản sao tới mọi child và từ Datum tới vùng chứa giá trị. Với NULL, hỏi cờ nằm ở đâu trước khi hỏi payload có bits gì.

Mức 2: câu 3 có kết quả số âm, nhưng chỉ kết quả đúng chưa kiểm được deep copy. Câu 4 cần xem owner và thời điểm slot invalidation; cờ NULL phải được giữ cùng giá trị. Câu 5 bỏ payload field NULL rồi căn chỉnh field kế tiếp từ offset hiện tại.

## Đáp án và lập luận

1. Cần p không NULL, trỏ đối tượng hợp lệ và tag/layout đúng subtype. Kiểm tag hoặc dispatch theo tag trước field access; sai type được báo theo contract. Cast C không đảm bảo validation; `castNode` dựa assertion khi được bật. Undefined/invalid access không có output/crash cố định để so. Tag cũng không cứu pointer vốn đã hết hạn.
2. Lấy cờ NULL từ interface. Nếu true, tạo output NULL và không decode d. Nếu false, xác nhận type từ descriptor/signature, dùng decoder integer hoặc text phù hợp. A.id=0, A.note=NULL, B.id=1, B.note=''. Chuỗi rỗng là một giá trị không NULL; pointer C không thay cờ SQL.
3. Multiply có hai child và nhánh nhân trong eval; clone sao hai subtree như Add. Trace 1+2=3, negate 4=−4, nhân=−12. Chứng minh cấu trúc thêm trường hợp hai child có giá trị đúng thì tích đúng; freshness/independence giữ theo cùng lập luận clone. Cây có sáu node, chi phí O(N), stack O(h); kiểm thay leaf 1 thành 5 làm gốc thành −28, bản sao vẫn −12. Nếu triển khai số nguyên C phải thêm miền/overflow contract; mô hình toán học chưa chứng minh phần đó.
4. Với integer by-value và isnull=false, sao giá trị đúng cách có thể đủ về payload; phải giữ type/null metadata. Với text by-reference, gán Datum chỉ sao reference và không kéo dài nguồn. Copy/convert sang vùng R trước clear/reuse, hoặc copy tuple qua API có ownership rõ. Với NULL, giữ cờ true và bỏ payload; không dereference. Output contract phải nêu sống đến khi R kết thúc.
5. Field 1 không có payload; field 2 bắt đầu offset 0, dùng byte 0–3; field 3 ở offset 4. Chiều dài, alignment, padding và NULL làm offsets thay đổi theo row. Các số thuộc mô hình minh họa; engine thật dùng descriptor, header và accessor riêng.

Một lời giải pseudocode tường minh cho Multiply ở câu 3 bổ sung trường hợp vào cả eval và clone, giữ nguyên các nhánh Literal/Add/Negate ở trên:

```text
eval(node):
    require node != NULL và tag/children hợp lệ
    switch node.tag:
        LITERAL:  return node.value
        ADD:      return eval(node.left)+eval(node.right)
        NEGATE:   return -eval(node.child)
        MULTIPLY: return eval(node.left)*eval(node.right)
        otherwise: error("unsupported node")

clone(node,R):
    require một cây hữu hạn hợp lệ, không cycle/sharing
    switch node.tag:
        LITERAL: return fresh Literal(node.value) trong R
        ADD: return fresh Add(clone(node.left,R),clone(node.right,R)) trong R
        NEGATE: return fresh Negate(clone(node.child,R)) trong R
        MULTIPLY:
            return fresh Multiply(clone(node.left,R),clone(node.right,R)) trong R
        otherwise: error("unsupported node")
```

Mỗi root/child được tạo mới đúng một lần; kiểm tập identity node của gốc và bản sao không giao nhau, rồi sửa leaf gốc để kiểm independence. Với cây sáu node đã cho, hai nhánh eval trả 3 và −4 rồi root trả −12. Nhánh Multiply trong chứng minh quy nạp dùng kết quả hai subtree nhỏ hơn, nên giữ cả giá trị lẫn freshness; chi phí theo N/h và miền số vẫn như mô hình ban đầu. Đây là đáp án model hoàn chỉnh, không phải node server hay C arithmetic đã được chạy.

## Biến thể và cách kiểm

Đổi thứ tự cột, thêm NULL, chuỗi rỗng, text dài hoặc cây sâu; không dùng malformed pointer thật trên server chung để làm quiz. Checker mô hình kiểm tag, cờ NULL, ownership graph và kết quả. Bài proof dùng rubric structural induction và copy contract. Feedback “cast đã chuyển object” phải cho thấy địa chỉ không đổi; feedback “copy Datum đã copy text” phải hiện alias còn chung.

Native test sau này cần pin source/build và kiểm cả text ngắn/dài, NULL, slot reuse, error path; không so byte-layout hard-code giữa các platform. Một output SQL đúng không xác nhận deep copy hay ABI. Trong lần bàn giao này, chỉ có nội dung, expected suy luận và đặc tả test; chưa có artifact build/load PostgreSQL cho hai bài.
