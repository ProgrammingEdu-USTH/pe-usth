## Chương trình không gửi “ý định”, nó gửi lệnh và dữ liệu

Người dùng chọn thành phố trên giao diện. Chương trình phải gửi câu query đến database, nhận các hàng rồi hiển thị. Nếu gộp nguyên văn input vào chuỗi SQL, ký tự người dùng nhập có thể trở thành cú pháp. Parameter binding tách phần cấu trúc câu lệnh khỏi phần giá trị.

Ta dùng Python vì mã ngắn; đây không phải điều kiện phải giỏi Python từ trước. `import` nạp thư viện; biến giữ một giá trị hoặc đối tượng; `def` tạo hàm; một khối thụt đầu dòng là phần thuộc hàm/vòng lặp/try. Cursor là đối tượng giao tiếp với kết quả và thao tác SQL qua connection, không phải con trỏ chuột trên màn hình.

Driver là thư viện biết giao thức database. Ví dụ dùng package `mysql-connector-python`; lệnh cài nếu môi trường học cho phép là `python -m pip install mysql-connector-python`. Một máy có MySQL Server chưa chắc Python đã có driver. Khác ngôn ngữ/driver có cú pháp placeholder khác; ví dụ `%s` dưới đây là giao diện của Connector/Python, không phải phép nội suy chuỗi Python.

## Mẫu đọc dữ liệu có tham số

Mã giả định server học có pe_shop và các biến môi trường `PE_DB_USER`, `PE_DB_PASSWORD` đã được người học cấu hình. Không chép mật khẩu thật vào tệp bài nộp.

```python
import os
import mysql.connector

def customers_in_city(city):
    connection = mysql.connector.connect(
        host=os.environ.get('PE_DB_HOST', 'localhost'),
        user=os.environ['PE_DB_USER'],
        password=os.environ['PE_DB_PASSWORD'],
        database='pe_shop'
    )
    cursor = connection.cursor()
    try:
        query = (
            'SELECT customer_id, customer_name '
            'FROM customers WHERE city = %s '
            'ORDER BY customer_id'
        )
        cursor.execute(query, (city,))
        return cursor.fetchall()
    finally:
        cursor.close()
        connection.close()

print(customers_in_city('Hanoi'))
```

Kết quả dự kiến là danh sách hai tuple `(1,'An')`, `(4,'Dung')`; kiểu hiển thị cụ thể có thể kèm dấu ngoặc của Python. `fetchall()` đọc các hàng còn lại trong result set. `(city,)` là tuple một phần tử, dấu phẩy có ý nghĩa; `(city)` chỉ là city được đặt trong ngoặc. `finally` giải phóng cursor/connection kể cả khi có lỗi. Chương trình thật còn cần xử lý lỗi, giới hạn truy vấn và quản lý connection phù hợp; mẫu này tập trung vào hợp đồng dữ liệu.

## Minh họa theo trạng thái

1. **T0:** input là chuỗi 'Hanoi', query là một chuỗi có một placeholder.
2. **T1:** chương trình gọi `execute(query,('Hanoi',))`; giá trị được gửi theo cơ chế parameter của driver, không nối vào cấu trúc query bằng f-string.
3. **T2:** query lọc customers, result set có hai hàng An,Dung theo thứ tự mã.
4. **T3:** fetchall trả danh sách tuple cho Python; connection chưa phải chính danh sách dữ liệu.
5. **T4:** finally đóng tài nguyên; dữ liệu đã đọc trong danh sách vẫn có thể dùng, nhưng không tiếp tục query qua cursor đã đóng.

Hoạt động thứ nhất: chú thích mỗi dòng mã theo vai connection/query/parameter/result. Hoạt động thứ hai: đổi input sang chuỗi chứa dấu nháy như `O'Brien`. Với binding, đó vẫn là một giá trị để so sánh; không phải lời kết thúc literal do ứng dụng tự ghép sai. Trên fixture không có thành phố ấy, nên kết quả rỗng là đúng, không phải lỗi cú pháp.

## Vì sao nối chuỗi là sai giao diện?

```python
# Ví dụ cần nhận diện và sửa; không dùng làm mẫu triển khai.
query = "SELECT customer_id FROM customers WHERE city='" + city + "'"
```

Một dấu nháy trong city làm cấu trúc SQL thay đổi hoặc gãy. Với input được chế tạo, ứng dụng có thể hỏi một điều kiện khác với người phát triển dự định. Cách sửa là placeholder cùng tuple tham số, không phải chỉ xóa một vài ký tự “nguy hiểm”. Parameter binding phục vụ **giá trị**. Không dùng `%s` để thay tên bảng, tên cột hoặc từ khóa ASC/DESC; các phần cấu trúc phải đến từ danh sách lựa chọn được ứng dụng cho phép.

Ví dụ người dùng chọn sort='price' hoặc 'name': ứng dụng ánh xạ hai lựa chọn ấy sang định danh cố định đã biết, không chấp nhận tên cột tùy ý. Binding và allowlist giải quyết hai loại input khác nhau; chúng cần phối hợp chứ không thay thế nhau.

## NULL và kiểu dữ liệu qua ranh giới ngôn ngữ

Python `None` đại diện trạng thái thiếu trong nhiều giao diện driver; SQL dùng NULL. Binding None vào điều kiện `city=%s` không biến dấu bằng thành IS NULL. Nếu mục tiêu là tìm khách city NULL, chương trình cần chọn query `WHERE city IS NULL` hoặc logic SQL được thiết kế cho trạng thái ấy. Đừng suy ra mọi city=None phải trả Chi.

DECIMAL có thể được driver trả dưới kiểu Decimal để giữ độ chính xác; không chuyển mọi tiền sang float chỉ để tiện hiển thị. Ngày có thể được trả bằng đối tượng date, không phải luôn chuỗi. Giao diện cần định nghĩa cách chuyển sang JSON/UI mà vẫn giữ semantics số và ngày.

## Ghi dữ liệu cần transaction và xử lý lỗi

Một đường ghi nên gọi commit sau khi toàn bộ đơn vị nghiệp vụ thành công, rollback khi thất bại và đóng connection trong finally. Ví dụ phần thân sau khi đã có connection/cursor:

```python
try:
    cursor.execute(
        'UPDATE products SET price=%s WHERE product_id=%s',
        (12, 11)
    )
    connection.commit()
except mysql.connector.Error:
    connection.rollback()
    raise
```

Đoạn này chủ động giữ giá12; chỉ chạy khi muốn thay fixture hoặc thay commit bằng rollback để luyện. Parameter binding không bảo đảm UPDATE đúng sản phẩm, không kiểm quyền người dùng cuối và không tự ngăn mọi race. Query có WHERE đúng và quyền tối thiểu vẫn cần; đường ghi nhiều bước còn cần chính sách transaction rõ.

## JDBC, ODBC và embedded SQL trong sách

Python là đường thực hành chính ở bài này, nhưng §5.1 còn giới thiệu ba cách nối chương trình với SQL. JDBC là API cho Java: Connection đại diện phiên kết nối; Statement gửi câu lệnh; PreparedStatement nhận query có placeholder rồi bind giá trị; CallableStatement phục vụ gọi routine. ResultSet cho duyệt các hàng bằng `next()` và đọc cột; metadata cho biết tên/kiểu cột hay thông tin schema. Metadata không phải chính các dòng dữ liệu. Ngoại lệ và đóng tài nguyên vẫn cần được xử lý như ở mẫu Python.

Đoạn Java sau là mẫu đọc mã, giả định đã có Connection `con` hợp lệ và JDBC driver cho MySQL. Nó không phải chương trình Java hoàn chỉnh hay điều kiện phải biết Java trước khi học khóa:

```java
String sql = "SELECT customer_id, customer_name FROM customers WHERE city = ?";
try (PreparedStatement stmt = con.prepareStatement(sql)) {
    stmt.setString(1, "Hanoi");
    try (ResultSet rows = stmt.executeQuery()) {
        while (rows.next()) {
            System.out.println(rows.getInt("customer_id"));
        }
    }
}
```

`?` nhận giá trị thứ nhất qua setString, không phải tên cột. Kết quả có hai mã 1 và 4 nhưng thứ tự không được bảo đảm vì query này không ORDER BY. `try (...)` quản lý việc đóng tài nguyên. Với DML, dùng phương thức phù hợp như executeUpdate và quản lý commit/rollback trên connection; không gọi executeQuery cho mọi loại statement. CallableStatement và OUT parameters cần hợp đồng routine cụ thể, không suy từ việc một SELECT đơn chạy được. [Tài liệu JDBC của Oracle](https://docs.oracle.com/javase/tutorial/jdbc/basics/prepared.html) minh họa các API này; cách tối ưu nội bộ còn tùy driver/engine, không hứa prepared statement luôn nhanh hơn.

ODBC là giao diện kết nối cho nhiều ngôn ngữ/hệ quản trị. Driver manager chuyển lời gọi đến driver phù hợp, driver nói chuyện với database. Một ứng dụng dùng API chung vẫn phải đối chiếu SQL dialect, types và transaction semantics; thay driver không tự biến câu SQL Server thành MySQL hợp lệ.

Embedded SQL đưa câu SQL vào mã host language, thường có dấu `EXEC SQL` và host variables. Precompiler biến phần SQL thành lời gọi thư viện trước bước biên dịch chương trình; các biến host truyền giá trị qua ranh giới ngôn ngữ. Cursor giúp lấy từng hàng và status báo tình trạng/error. Dynamic SQL xây/prepare câu lệnh tại runtime, khác với việc toàn bộ SQL đã cố định trong nguồn embedded. Đây là khái niệm của sách, không phải cú pháp Python/Java thuần hay `EXEC SQL` chạy trực tiếp trong MySQL client.

## Biến thể và lỗi thường gặp

Biến thể gồm input thường, Unicode, dấu nháy, None, ngưỡng không có kết quả và lựa chọn sort sai. Không đưa credentials thật vào seed hoặc tài liệu log. Ca biên lỗi giữa hai câu ghi phải kiểm rollback toàn đơn vị nghiệp vụ. Phản hồi cho lỗi binding nên chỉ ra chỗ dữ liệu bị biến thành cấu trúc, không chỉ nói “dùng prepared statement cho an toàn” mà không có mã đúng.
